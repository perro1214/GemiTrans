# GemiTrans - AI Page Translator

Geminiなど複数のLLMプロバイダーを使用してウェブページをリアルタイム翻訳するChrome拡張機能です。

## 機能

- ワンクリックでページ全体を翻訳
- 複数言語対応（日本語・英語・中国語・韓国語など）
- 複数のGeminiモデル選択（Gemini 2.0 Flash / 2.5 Pro など）
- 複数プロバイダー対応（Gemini / OpenRouter / SambaNova / NVIDIA API / Cerebras API / PlaMo API / OpenCode Go / ロリポップ！AI Gateway / ローカルAPI）
- 自動翻訳モード（ページを開いた時に自動実行）
- バッチ翻訳による高速処理
- リトライ機能付き（レート制限・サーバーエラー対応）
- 翻訳のキャンセル・原文復元
- エラーログ表示

## インストール方法

1. このリポジトリをクローンまたはZIPでダウンロードします
   ```bash
   git clone https://github.com/perro1214/GemiTrans.git
   ```

2. Chromeで `chrome://extensions/` を開きます

3. 右上の「デベロッパーモード」をオンにします

4. 「パッケージ化されていない拡張機能を読み込む」をクリックし、クローンしたフォルダを選択します

## 使い方

1. [Google AI Studio](https://aistudio.google.com/apikey) で Gemini API キーを取得します

2. 拡張機能のポップアップを開き、API キーを入力して「設定を保存」をクリックします

3. 翻訳したいページで「✨ ページを翻訳」ボタンをクリックします

4. ショートカットキー `Alt+T` でも翻訳を実行できます

### ロリポップ！AI Gateway を使う

1. [ロリポップ！AI Gateway](https://ai-gateway.lolipop.jp/docs/guides/welcome)でプロジェクトのAPIキーを発行し、組織・ルール・APIキーで利用するモデルを許可します。
2. Chromeの拡張機能管理画面でGemiTransを再読み込みし、ポップアップのAPIプロバイダーに「ロリポップ！AI Gateway」を選択します。
3. APIキーを入力して「APIでモデル一覧を取得」を押し、モデルを選択します。「設定を保存」を先に押した場合もモデル一覧を取得し、先頭のモデルを選択します。
4. 「設定を保存」で接続を確認し、「ページを翻訳」を押します。接続テストでは短い翻訳リクエストを送信します。

接続先は `https://ai-gateway.lolipop.jp/v1/chat/completions`、認証は `Authorization: Bearer` です。モデルは認証付きの `GET /v1/models` から取得し、返された公開IDをそのまま使います。`auto` が一覧に含まれる場合はGateway側の自動選択を利用できます。キーやモデルの許可設定を変更した場合は一覧を再取得してください。トークン使用量は実際に応答したモデルごとに記録します。料金はGatewayの使用状況画面で確認してください。

### Hy-MT2 を MLX で使う

Apple Silicon Mac では Tencent Hunyuan の Hy-MT2 を `mlx-lm` の OpenAI 互換サーバー経由で利用できます。

```bash
uvx --python 3.12 --from mlx-lm mlx_lm.server \
  --model mlx-community/Hy-MT2-7B-4bit \
  --host 127.0.0.1 --port 8080 \
  --temp 0.7 --top-p 0.6 --top-k 20 --max-tokens 4096
```

拡張機能側では API プロバイダーに `ローカルAPI (llama.cpp / LM Studio / MLX)` を選び、エンドポイントを `http://127.0.0.1:8080`、モデルを `mlx-community/Hy-MT2-7B-4bit` に設定します。16GB メモリ環境で重い場合は `mlx-community/Hy-MT2-1.8B-4bit` を試してください。

### GTX 1080 の Gemma 4 26B を使う

`192.168.11.20` の WSL2 に構築済みの llama.cpp サーバーは、次のスクリプトで常駐起動できます。

```bash
bash scripts/gemitrans-gemma4-server.sh start
```

拡張機能側では API プロバイダーに `ローカルAPI (llama.cpp / LM Studio / MLX)` を選び、エンドポイントを `http://192.168.11.20:8080`、モデルを `gemitrans-gemma4`、バッチ許容量を `小（1500文字）` に設定します。

この構成は Gemma 4 26B A4B の MoE層を GTX 1080 8GB とCPUへ分担し、思考出力を無効化します。実測で有効だった主な llama.cpp 設定は `-ngl 30 -ncmoe 16 -fa on --no-mmap -np 1` です。

### GTX 1080 の高速翻訳モード

速度と日本語品質を両立する場合は、Gemma 4 E2B QAT GGUFを使用します。

```bash
bash scripts/gemitrans-gemma4-e2b-server.sh start
```

拡張機能側ではエンドポイントを `http://192.168.11.20:8080`、モデルを `gemitrans-gemma4-e2b` に設定します。ローカルAPI経路だけでGemma 4 E2Bを自動判定し、12件バッチを2並列で処理します。55件の同一ベンチマークは約7.8〜8.6秒、VRAM使用量は約3.2GBでした。

翻訳専用の軽量モデルを使う場合は、Hy-MT2 1.8Bを使用します。

```bash
bash scripts/gemitrans-hymt2-server.sh start
```

拡張機能側ではエンドポイントを `http://192.168.11.20:8080`、モデルを `gemitrans-hymt2-1.8b` に設定します。GemiTransはこのモデルを自動判定し、番号付き大バッチではなく個別翻訳を2並列で実行します。

55件の同一ベンチマークでは、Gemma 4 26Bの約87秒、Hy-MT2 1.8Bの約9.8秒に対し、Gemma 4 E2Bは約7.8〜8.6秒でした。

## Kaggleノートブックの翻訳

Kaggleのノートブック本文（kaggleusercontent.comのiframe）にも対応しています。「ページを翻訳」および自動翻訳でMarkdownセルの見出し・説明文・箇条書き・表を翻訳します。コードセル、実行結果・ログ、数式、インラインコードは保持します。親ページのキャンセル・原文復元は本文にも適用されます。コードコメントの別表示翻訳はこの機能には含まれません。

検証: `node --test tests/*.test.mjs`


### 文脈を保って並列翻訳（任意）

ポップアップの「文脈を保って並列翻訳」で切り替えます。初期値はOFFで、変更は次回のページ翻訳に適用されます。OFFは従来の文字数分割・並列数です。

ONはMarkdownセル、表の行、段落などのDOMブロック境界を優先して約2,600文字までにまとめ、ページごとに設定した並列数（1〜6、初期値3）で処理します。大きすぎるブロックはテキストノード間で分割し、単一ノード自体は壊しません。ページ見出し（最大500文字）と適格な周辺文章を、合計最大1,200文字の翻訳対象外の参照情報として送ります。コードやフォーム入力値を参照用に取得しません。ローカルモデルでは参照を600文字に抑えます。

参照情報はキャッシュ識別条件にも含めます。ON/OFFの切替や参照文の変化により初回のキャッシュヒットは減ります。参照文を繰り返し送る分だけ入力トークン・料金が増える場合があります。速度改善と訳語の一致は保証しません。用語集をAIで事前生成する追加リクエストは行いません。

Kaggleの遅延ロードされたノートブックにも開始時の設定を引き継ぎます。動的更新の追加翻訳は従来どおり順次処理し、文脈付き分割と参照情報のみ適用します。設定した並列数は初回・再スキャンのバッチと、全タブ共通のLLM通信キューに適用します。Google仮翻訳は別キューです。


### キャッシュ容量と並列数

- 保存キャッシュはサイト（ホスト）ごとに20MiBのUTF-8 JSON容量を上限とし、2,000件制限を廃止しました。キー・原文・訳文・文脈・日時も容量に含めます。上限以下なら2,000件を超えて保持できます。サイト別キャッシュ表示に使用量と上限が出ます。
- 容量超過時は最終使用時刻の古い順（LRU）で削除します。既存v3キャッシュはそのまま読み、最終使用時刻のない項目は保存日時を使用します。メモリヒットも保存キャッシュの使用記録へ反映します。20MiBを超える単一項目は保存せず、既存の有用なキャッシュを追い出しません。
- 使用時刻はメモリでまとめ、サイトごとに最大1分に1度のアクセス時、または次の訳文保存時に永続化します。書き込み回数を抑えるための近似LRUであり、サービスワーカー停止直前の未保存の使用時刻は失われる場合があります。保存エラーは翻訳結果を失わせずログに記録します。
- 通常ログにもメモリ／ストレージのヒット数・未ヒット数・ヒット率と、保存時の容量超過削除数・サイト容量を記録します。未ヒット数は実際のAPI呼び出し数ではありません（重複リクエスト共有があるため）。
- 「文脈付き翻訳の並列数」は1〜6、初期値3。設定は次回の翻訳から適用し、OFF時は従来方式、ON時の参照文や分割サイズは変えません。この拡張内のLLM通信キューには再試行・単文フォールバックと他タブも含めます。別ブラウザーや外部アプリを含むアカウント全体の上限ではありません。

### ページ遷移中の翻訳とキャッシュ

- ページ遷移を検出すると、旧ページへの反映と未送信の追加リクエストを停止します。
- 送信済みの応答は最後まで受信し、有効な訳文を通常の文脈付きキャッシュへ保存します。遷移後に不要となった再試行・フォールバックは送信しません。
- 他のページも同じ翻訳を待っている場合は、共有処理を継続します。
- 全タブ・LLMプロバイダーの翻訳通信を共通キューで管理します。文脈付き並列化ON時は設定した並列数、OFF時は3通信を上限とし、応答本文の受信まで枠を保持します。APIキーの接続確認・モデル一覧取得は対象外です。
- 空いた枠には新しいページの処理を優先します。送信済みの旧処理が枠を使用中の場合、新ページは完了を待ちます。上限を下げた場合も送信済み通信は中断せず、完了してから新しい上限を適用します。


### Google仮翻訳 → LLM翻訳

設定の「Googleで先に仮翻訳」をONにし、Google Cloud Translation APIキーを入力して「設定を保存」を押すと利用できます。既定はOFFです。Google CloudプロジェクトでCloud Translation APIと課金を有効にしてください。Gemini用キーを自動流用しません。

- 原文をGoogle Cloud Translation Basic v2（NMT）と選択中のLLMへ並行送信します。Googleの結果が先に届けば仮表示し、LLMの結果が届いた箇所から置き換えます。LLMにはGoogleの訳文ではなく原文を渡します。
- LLMキャッシュにある項目はGoogleへ送信しません。仮訳はLLMキャッシュへ保存しません。
- LLMが先に完了した場合、Googleの遅い結果で表示を戻しません。Googleの失敗はLLM翻訳を止めず、LLMの失敗時は取得済みの仮訳を残して未完了を通知します。
- 原文復元・キャンセル・ページ遷移後の遅い応答、サイト自身によるテキスト更新を保護します。原文復元は仮訳からも元の原文へ戻します。
- ページ全体、動的追加コンテンツ、再スキャン、Kaggleの対象iframeで利用します。選択範囲・入力欄の翻訳は従来のLLM翻訳です。
- Google通信はLLMの待ち行列とは別に全タブ共通で最大2通信、バッチ全体で最大8秒です。1リクエストは最大128項目・合計5,000コードポイント。単一項目が5,000コードポイントを超える場合、仮訳を省略してLLMで処理します。
- Googleの文字数課金がLLM料金に追加されます。既存のトークン・推定料金表示にGoogle分は含みません。

公式仕様: [Cloud Translation Basic v2](https://cloud.google.com/translate/docs/reference/rest/v2/translate)


### 日本語ページのスキップ

翻訳先が日本語の場合、日本語を含む本文を翻訳APIへ送りません。日本語ページに短い英語の商品名・ナビゲーション・著作権表示があるだけでは翻訳を開始せず、後から読み込まれる日本語にも同じ判定を適用します。英語の本文やディスカッションの見出しが混在する場合は、一定の長さがある英語部分のみを翻訳します。判定は文字種・文章の長さ・DOM上の役割によるため、短い英語見出しなどは省略される場合があります。必要な箇所は選択範囲翻訳を利用できます。日本語から英語など、翻訳先が日本語以外の場合はこの除外を行いません。

### 翻訳箇所の下線・原文表示

ポップアップで「翻訳した箇所に下線を表示」と「マウスを重ねると原文を表示」を個別にON/OFFできます。初期値はどちらもON。変更は即時保存され、翻訳済みのページやKaggleの本文にも反映します。再翻訳やAPIキーの接続確認は不要です。

下線はテキスト範囲の描画だけを変更し、文字サイズ・行の高さ・DOM構造を変えません。サイト本来の下線やテキスト直上の下罫線がある場合は追加せず、OFFでもサイト本来の装飾は残ります。原文復元は表示設定にかかわらず利用できます。下線にはCSS Custom Highlight APIに対応するChromeが必要です。
